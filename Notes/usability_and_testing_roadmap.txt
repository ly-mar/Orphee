3. WHAT REMAINS TO BE DONE FOR FULL COMMERCIAL VIABILITY
================================================================================

To take TuneHub from its current rock-solid development state to a commercially 
viable, App Store-approved, production-ready product, the remaining roadmap focuses 
on the following four areas:

--------------------------------------------------------------------------------
AREA 1: CLOUD BACKEND DEPLOYMENT (P0)
--------------------------------------------------------------------------------
1. Deploy Production Firestore & Storage Rules
   - Status: Rules files (`firestore.rules` and `storage.rules`) are authored and verified locally.
   - Action Required: Deploy to the live Firebase project using Firebase CLI:
     ```bash
     firebase deploy --only firestore:rules,storage:rules
     ```
   - Viability Impact: Prevents unauthorized user document overwrites and protects user data.

2. Deploy Affinity Matrix Cloud Function (`functions/index.js`)
   - Status: Cloud function logic written and structured.
   - Action Required: Deploy functions to Firebase Cloud Functions:
     ```bash
     cd functions && npm install && cd ..
     firebase deploy --only functions
     ```
   - Viability Impact: Offloads heavy computation from mobile devices to the cloud, 
     enabling infinite user scaling without client lag or battery drain.

--------------------------------------------------------------------------------
AREA 2: APP STORE & GOOGLE PLAY COMPLIANCE (P1)
--------------------------------------------------------------------------------
1. In-App Account Deletion (Apple App Store Guideline 5.1.1(v) - Mandatory)
   - Status: User blocking/reporting completed in `UserProfileScreen.js` and `ChatScreen.js`.
   - Action Required: In `SecuritySettings.js`, add a dedicated "Delete Account" button that:
     * Prompts for confirmation.
     * Deletes user documents (`users/{userId}`, `playlists/{userId}`, `memoirs/{userId}`).
     * Deletes stored profile image from Storage.
     * Calls `auth.currentUser.delete()`.
     * Navigates back to `WelcomeScreen`.
   - Viability Impact: Apple rejects any app with account creation that lacks in-app account deletion.

2. Hosted Privacy Policy & Terms of Service
   - Action Required: Host a standard mobile privacy policy and terms of service (covering 
     photo uploads and music listening data) on a public URL and link it inside 
     `SettingsScreen.js` and `WelcomeScreen.js`.
   - Viability Impact: Mandatory requirement for App Store review and Google Play publishing.

--------------------------------------------------------------------------------
AREA 3: PRODUCTION BUILD & NATIVE IDENTITY (P2)
--------------------------------------------------------------------------------
1. Production App Identity in `app.json`
   - Action Required:
     * Replace bundle identifier `com.anonymous.TubeApp` with registered ID: `com.tunehub.app` (or `com.tunehub.chorus`).
     * Set matching Android package: `com.tunehub.app`.
     * Ensure high-resolution production app icons are configured in `assets/icon.png` (1024x1024) 
       and `assets/adaptive-icon.png`.
     * Verify splash screen configuration (`assets/splash.png`).

2. EAS Build Setup (`eas.json`)
   - Action Required: Configure Expo Application Services build profiles for iOS and Android:
     ```bash
     npx eas-cli build:configure
     ```
   - Viability Impact: Enables automated cloud compiling of standalone `.ipa` and `.aab` production bundles.

--------------------------------------------------------------------------------
AREA 4: PUSH NOTIFICATIONS & RETENTION ENGAGEMENT (P3)
--------------------------------------------------------------------------------
1. APNs / FCM Production Push Notification Credentials
   - Status: Registration and push dispatch helpers are wired in `App.js`, `HandlingFriends.js`, 
     and `ChatScreen.js`.
   - Action Required: In Expo dashboard / EAS credentials, upload the Apple Push Notification 
     Key (`.p8`) and Google Cloud Messaging Server Key so push notifications trigger on 
     real iOS and Android hardware when apps are closed.
   - Viability Impact: Critical for social app retention (notifying users of friend requests, 
     direct messages, and daily music drops).
